# 貢獻指南

感謝你對踩地雷 AI 教學遊戲的興趣！本指南將幫助你開始貢獻。

## 如何貢獻

### 報告問題

如果你發現了 bug 或有功能建議：

1. 檢查[常見問題](faq.md)和[故障排除](troubleshooting.md)是否已有解答
2. 在 GitHub 上建立 Issue
3. 提供詳細的問題描述和重現步驟

### 提交程式碼

1. Fork 專案
2. 建立功能分支：`git checkout -b feature/amazing-feature`
3. 提交變更：`git commit -m 'Add amazing feature'`
4. 推送到分支：`git push origin feature/amazing-feature`
5. 建立 Pull Request

## 開發規範

### 程式碼風格

- 遵循 PEP 8 Python 風格指南
- 使用 4 個空格縮排
- 行長度限制 100 字元
- 使用類型提示（Type Hints）

### 提交訊息

使用清晰的提交訊息：

```
feat: 添加教學模式功能
fix: 修復計時器不準確的問題
docs: 更新安裝指南
style: 格式化程式碼
refactor: 重構遊戲引擎
test: 添加單元測試
```

### 測試

- 新功能應該包含測試
- 確保所有測試通過
- 測試覆蓋率應該維持在合理水平

## 貢獻領域

### 程式碼貢獻

- 修復 bug
- 添加新功能
- 改進現有功能
- 優化效能
- 重構程式碼

### 文檔貢獻

- 改進現有文檔
- 添加新的指南
- 修正錯誤
- 翻譯文檔

### 設計貢獻

- UI/UX 改進
- 視覺設計
- 使用者體驗優化

## 開發流程

### 1. 設置開發環境

參考[開發環境設置](development-setup.md)

### 2. 選擇任務

- 查看 GitHub Issues
- 選擇感興趣的任務
- 在 Issue 中留言表示要處理

### 3. 開發

- 建立功能分支
- 實作功能
- 添加測試
- 更新文檔

### 4. 提交

- 確保程式碼通過所有測試
- 確保符合程式碼風格
- 提交 Pull Request

### 5. 審查

- 回應審查意見
- 進行必要的修改
- 等待合併

## 程式碼審查標準

### 功能

- 功能是否正確實作？
- 是否有邊界情況處理？
- 是否有適當的錯誤處理？

### 程式碼品質

- 程式碼是否清晰易讀？
- 是否有適當的註解？
- 是否有重複程式碼？

### 測試

- 是否有適當的測試？
- 測試是否通過？
- 測試覆蓋率是否足夠？

### 文檔

- 是否有更新相關文檔？
- 是否有適當的 API 文檔？

## 行為準則

### 我們的承諾

- 尊重所有貢獻者
- 歡迎不同的觀點和經驗
- 優雅地接受建設性批評
- 專注於對社群最有利的事情

### 不可接受的行為

- 使用性別化的語言或評論
- 人身攻擊
- 公開或私下的騷擾
- 發布他人的私人資訊
